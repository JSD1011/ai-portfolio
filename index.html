Important Engineering Decisions

Chunking and embeddings dictate retrieval bounds. I prioritized configurable windowing and context isolation.

Engineering Principles

How I Approach AI Engineering

Core convictions derived from debugging real multi-agent flows, vector search edge cases, and schema explosion challenges.

01

Model Is Only One Component

An LLM alone is not the complete application. Reliability stems from the orchestration harness, routing logic, validation layers, and structured error recovery surrounding it.

02

Give Agents Tools

Agents become useful when they can retrieve verified information, query operational databases, or interact with external system APIs deterministically rather than guessing answers.

03

Control the Context

Relevant context is often more important than simply increasing the model parameter size. Intelligent schema pruning and noise filtering preserve attention and prevent hallucination.

04

Validate LLM Output

Generated SQL and other structured outputs should be validated before execution or downstream consumption. Deterministic syntax parsers and type validators protect the database and application layers.

05

Modular Workflows

Complex AI applications should be divided into understandable, testable components and specialized agents. Single-prompt monolithic chains fail unpredictably; decomposed state graphs fail gracefully.

Real Engineering Insights

Engineering Challenges

Practical obstacles encountered and tackled while developing agent workflows, RAG retrievers, and SQL generation pipelines.

CHALLENGE 01 Information Retrieval

Retrieval Quality

How to retrieve useful context instead of irrelevant chunks.

Raw similarity metrics can return semantically close but contextually irrelevant fragments. Mitigated by testing boundary-aware chunking, hybrid keyword/vector search, and context filtering before feeding prompt templates.

CHALLENGE 02 Context Management

Context Size

How to avoid sending unnecessary information to the LLM.

Large contexts incur latency, increase cost, and dilute the model's focus ("lost in the middle"). Solved by strict token budget allocation and dynamic schema filtering tailored to the user's specific query intent.

CHALLENGE 03 Relational Data

Database Schema Complexity

How to deal with large database schemas in Text-to-SQL.

Real enterprise databases contain dozens of tables with complex foreign keys. Dumping complete DDLs fails prompt limits and induces foreign key hallucination. Tackled via dedicated Column Selection agents that prune tables.

CHALLENGE 04 Safety & Guardrails

SQL Reliability

How to validate generated SQL before execution.

LLMs can occasionally output syntactically invalid SQL, Cartesian joins, or destructive clauses. Built deterministic pre-execution validation checks that parse ASTs, restrict queries to read-only semantics, and verify column existence.

CHALLENGE 05 Multi-Agent Control

Agent Orchestration

How to divide a complex workflow into specialized agents.

Single monolithic agents lose track of sub-goals. Designed LangGraph cyclic graphs where responsibilities are cleanly isolated: Routing → Schema Pruning → SQL Generation → Validation, with explicit state schemas.

CHALLENGE 06 Inference Trade-offs

Model Selection

How to decide between hosted and open-source models.

Evaluating hosted endpoints (OpenAI, Bedrock) against self-hosted models (Ollama, SQLCoder on vLLM). Balance considerations include data privacy, inference latency, cold starts, cost per token, and domain-specific SQL specialization.
